      \vspace{.15cm}
      \begin{block}{DNS: measurements}

RPKI là tập bản ghi uỷ quyền định tuyến quan sát theo ngày; so sánh thành viên giữa hai ngày đầy đủ, không suy ra chính xác thao tác của quản trị viên. DNS là phép đo truy vấn và phản hồi: thấy tên miền trả về địa chỉ nào tại thời điểm quan sát, không coi đó là toàn bộ trạng thái DNS. Ví dụ trên slide chỉ minh hoạ cách hiểu. Điểm chung là cần lưu lịch sử; cách định nghĩa thay đổi phải riêng cho từng loại.}

\begin{frame}{A commit manifest marks readable history}
  \centering
  \includegraphics[width=\linewidth,height=3.8cm,keepaspectratio]{commit-order.png}
  \begin{flushleft}
    \textbf{Readers use committed files.} Partial writes stay outside accepted history.\\[5pt]
    An exact retry verifies and reuses the committed batch.
  \end{flushleft}
  \source{Current lake-enabled code: spark/streaming/sinks/lake.py; spark/streaming/outputs.py.\\
  No atomic transaction across sinks. Latest integrity changes still need a completed Kubernetes recovery rerun.}
  \vnote{Khoảng 45 giây. File xuất hiện trên MinIO chưa có nghĩa batch đã hoàn tất. Với code hiện tại, Spark ghi Parquet, lập inventory đường dẫn, kích thước và SHA-256, đọc lại theo schema để kiểm tra số dòng, rồi mới publish manifest. Reader chỉ đọc các đường dẫn được manifest khai báo. Sau đó callback mới index metadata, gửi alerts và trả quyền điều khiển để Spark tiến hành checkpoint. Nếu batch đã commit mà bước sau lỗi, retry kiểm tra đầy đủ projection, kể cả số lần xuất hiện của dòng, rồi tái sử dụng Parquet. Cảnh báo Kafka vẫn có thể lặp về mặt vật lý; không có giao dịch atomic xuyên các sink. Phần integrity mới đã có kiểm thử local nhưng lần recovery trên Kubernetes của image mới nhất chưa hoàn tất, nên không gán bằng chứng deployment cũ cho nó.}
\end{frame}

\begin{frame}{Kafka: an offset is not a configuration version}
  \begin{columns}[T,onlytextwidth]
    \begin{column}{.48\textwidth}
      \begin{block}{Three configuration input topics}
        \texttt{config.assets}: asset metadata\par\medskip
        \texttt{config.events}: audit events\par\medskip
        \texttt{config.snapshots}: versioned input
      \end{block}
    \end{column}
    \begin{column}{.48\textwidth}
      \begin{block}{What the processor reads}
        Spark reads \texttt{config.snapshots}.\par\medskip
        Kafka keys use \texttt{asset\_id}.\par\medskip
        Offsets locate records within a partition.
      \end{block}
    \end{column}
  \end{columns}
  \keyline{Partition order preserves delivery order, not source-version order.}
  No total order or atomic publication across these topics.
  \source{messaging/kafka\_producer.py; spark/streaming/kafka\_source.py; docs/kafka-topics.md.}
  \vnote{Slide phụ, không tính vào thời gian trình bày chính. Kafka tách nguồn phát khỏi processor và cho phép replay khi record còn retention. Asset, event và snapshot là ba loại thông điệp riêng. Spark dùng snapshot để xử lý state; không đợi event ở topic khác xuất hiện trước. Cùng asset ID giúp phân vùng, nhưng producer có thể gửi v3 trước v2 nên offset không thay được số phiên bản. Không giả định thứ tự hoặc atomicity giữa các topic.}
\end{frame}

\begin{frame}[fragile]{Parquet layout separates raw evidence and processed history}
  \begin{columns}[T,onlytextwidth]
    \begin{column}{.43\textwidth}
\begin{lstlisting}[basicstyle=\ttfamily\footnotesize]
config-lake/
  raw/snapshots/
  processed/snapshots/
  processed/diffs/
  processed/alerts/
  processed/diagnostics/
  _commits/
  analytics/
\end{lstlisting}
    \end{column}
    \begin{column}{.53\textwidth}
      \textbf{Raw}: binary Kafka key/value, topic, partition, offset and timestamp.\par\medskip
      \textbf{Processed}: typed snapshots, diffs, alerts and diagnostics.\par\medskip
      Each configuration batch has a query/batch namespace and UTC date partitions.
    \end{column}
  \end{columns}
  \medskip
  {\small Example: \texttt{processed/snapshots/query\_id=.../batch\_id=.../year=2026/month=10/day=5/}}
  \source{spark/streaming/sinks/lake.py; docs/data-lake.md. Configuration layout only; other domains use separate temporal paths.}
  \vnote{Slide phụ. Đây là layout của đường cấu hình, không phải schema chung cho cả bốn loại dữ liệu. Raw giữ byte Kafka và provenance; processed giữ các output đã chuẩn hoá. Query ID và batch ID xác định vùng ghi, còn year/month/day giúp đọc theo ngày. Ngày của raw lấy từ Kafka timestamp; ngày của các output khác lấy theo loại record. Kafka partition là phân vùng log, Spark execution partition là phân công xử lý, date partition là tổ chức file: ba khái niệm khác nhau. Chỉ raw được query fetch trong retention mới có thể lưu; không thể khôi phục record đã bị Kafka xoá trước khi đọc.}
\end{frame}
